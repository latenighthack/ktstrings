# Catalog and runtime contract

Place `catalog.json` and optional `locales/<locale>.json` files under the owning project's `localization/` directory. Versioned structural schemas are in `schema/`; the compiler additionally enforces duplicate-property, locale, placeholder, name-collision, and CLDR semantic rules. One Gradle project owns one namespace.

Namespace identifiers are lowercase ASCII identifiers. IDs contain dot-separated ASCII identifier segments; argument names are ASCII identifiers. Generated names are checked for collisions across Kotlin, Swift, TypeScript, Android, and Objective-C. Prototype-sensitive JavaScript names, reserved language/API names, and argument properties conflicting with the shared message boundary are rejected. Collisions report both IDs and the conflicting generated identifier.

Locale input accepts hyphens or underscores and normalizes to BCP 47 language/script/region casing (`en_us` becomes `en-US`). The compiler requires an ICU-supported language and rejects locale extensions/private-use tags for catalog identity. The normalized file-name locale must match its translation document, and duplicate normalized locales are rejected. Runtime requested locales can carry extensions; those do not identify a separate catalog.

Bodies contain either `text`, or one integer-cardinal `plural` selector and complete text `cases`. `{name}` interpolates a declared argument, while `{{` and `}}` escape literal braces. Literal percent signs, quotes, backslashes, newlines, Unicode, and i18next-looking content survive compilation. Translations may reorder, repeat, or omit placeholders, but cannot add arguments, IDs, nested bodies, or change a message's text/plural contract or selector. A supplied plural must include all categories required by the compiler's pinned CLDR data, including uncommon French `many`; English `zero` is rejected because it has incompatible grammatical semantics. Exact-number, ordinal, fractional, nested, and arbitrary ICU expressions are outside V1.

Arguments are non-null strings or signed 32-bit integers. Plural selectors require a nonnegative integer. Declaration order establishes native format positions. A plural selector with a name other than `count` cannot coexist with a distinct `count` argument. The compiler pins ICU4J 78.3 and records its reported CLDR data version in generated metadata.

Generated `Messages` functions return concrete immutable message types. Arguments remain values until presentation, and equality/hash behavior supports state comparison. Native resolvers and the React resolver select one complete message by exact locale, progressively less-specific locale, then source locale before native/i18next formatting. Locale changes do not require replacing ViewModel message values.

`ServerLiteral` and `ServerMessage` are transport-neutral boundary types; runtime consumers do not require a JSON library. Adapt transport arguments into `ArgumentValue.StringValue`, `IntValue`, or `NumberValue` (the last retains a numeric wire value for strict range/integrality validation). Unsupported values can become `InvalidValue`. `Messages.decode(value, genericFallback, diagnostics?)` validates namespace, ID, exact argument names, types, integer limits, and selector quantity, then calls the same typed constructors. Unknown/invalid references use present `fallbackText`, including empty strings, otherwise the required generic fallback. Diagnostics include only code and message identity; they never include argument or literal content.

The JVM compiler also exposes `validate`, `coverage`, and `generate` commands. Generation options use `--catalog`, `--output`, `--kotlin-package`, `--android-package`, `--framework-name`, `--framework-bundle-id`, `--react-package`, `--react-version`, and `--platforms` (`kotlin,android,apple,react`). Prefer the published Gradle plugin for automatic build and artifact wiring.
